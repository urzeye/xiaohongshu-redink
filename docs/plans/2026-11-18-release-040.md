# v0.4.0 Release Workflow Implementation Plan

**Goal:** Republish v0.4.0 through one desktop release run, without automatically building or publishing Docker images.

**Architecture:** `release.yml` is the only tag-triggered entry point. It calls `desktop-release.yml` to build Windows and macOS installers, then publishes the release only after both builds succeed. Docker remains available through manual dispatch.

**Tech Stack:** GitHub Actions, Tauri v2, pnpm 11.7.0, Rust 1.100.0, GitHub CLI.

## 1. Update the workflows

- `.github/workflows/docker-publish.yml`: remove tag triggers; preserve the file and manual publishing.
- `.github/workflows/desktop-release.yml`: accept `workflow_call` only; install both real macOS Rust targets; build and upload installers without creating a release; limit job duration.
- `.github/workflows/release.yml`: keep one tag trigger; call the desktop builder; download and verify all three installers before creating the release; describe the current local backend requirements accurately.
- `docs/TAURI_DESKTOP.md`: document the release entry point and current runtime packaging limitation.

## 2. Verify locally before publishing

- Run actionlint against all workflow files.
- Validate the trigger graph and action inputs, and verify that the version files agree with v0.4.0.
- Install dependencies using the frozen lockfiles, then run the frontend production build.
- Run a Windows desktop release build locally. macOS cannot be built on this Windows host; verify the Rust targets and Tauri options against official documentation.
- Run `git diff --check` and review the final diff. Do not dispatch, rerun, or use GitHub Actions for testing.

## 3. Republish exactly once

- Commit the reviewed changes and push `main`; this must not trigger Actions.
- Delete only the old v0.4.0 Release and tag, preserving historical workflow runs and other releases.
- Recreate v0.4.0 at the fixed commit and push that tag once.
- Observe the one production run with read-only requests. Do not automatically rerun a failed production job.
- Verify that only the intended workflow ran and that the release contains Windows NSIS/MSI and macOS DMG installers.
